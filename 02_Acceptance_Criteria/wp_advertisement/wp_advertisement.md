## User Story

**As a** Web Portal Admin
**I want** to choose between **Advertisement** type (the existing scheduled banner/video shown on the Damage page) and **Banner** type (upload a banner and assign it to one or more specific pages), with only the fields relevant to the chosen type shown
**So that** I can target promotional banners to specific app pages while keeping the existing Damage-page advertisement scheduling behavior intact

## Column Guide

| Column          | Description                                                       | Values / Format                                   |
| --------------- | ---------------------------------------------------------------- | ------------------------------------------------- |
| **AC ID**       | Unique scenario id — TCs trace back to this                      | `AC-WPAD-NN`                                       |
| **Rule ID**     | Unique business-rule id — TCs trace back to this                 | `BR-WPAD-NN`                                       |
| **Scenario**    | Short title of the behaviour, start with an action verb          | Plain text                                         |
| **Jira**        | The ticket this AC came from                                     | `[RC-115](url)`                                    |
| **Type**        | Class of scenario                                                | Happy / Alternate / Negative / Edge / Permission   |
| **Criticality** | Impact if this AC fails — drives the verifying TC's priority     | 🔴 Critical / 🟠 High / 🟡 Medium / ⚪ Low          |
| **Given**       | Precondition / context true before the action                    | One state per clause; `<br>And …` to compound      |
| **When**        | The single action or event that triggers behaviour               | One trigger                                        |
| **Then**        | Observable, verifiable outcome — pass/fail must be objective      | Include error code / message / state where relevant |
| **Linked TCs**  | TCs in `03_Testcases/wp_advertisement/wp_advertisement.md` that verify this AC | `TC-WPAD-NNN`, comma-separated  |
| **Status**      | Review state of the criterion                                    | Draft / Reviewed / Approved                        |

## Traceability

```
Jira ticket  ──▶  AC-WPAD-NN / BR-WPAD-NN  ──▶  TC-WPAD-NNN
 (the why)         (the what — this file)              (the how to verify)
```

- **Upward**: header `SRS ref` + each row's `Jira` column link the AC to its source (RC-115).
- **Downward**: the `Linked TCs` column lists the test cases that verify each AC — to be filled by `/gen-tc`.
- **Coverage rule**: every `Critical` and `High` AC and every business rule must have ≥1 Linked TC. Flag any such AC with zero TCs as a coverage gap. Conversely, every TC must name the `AC` it verifies — no orphan TCs.
