## User Story

**As a** Repair Check web-app user (guest or logged in)
**I want** to see a Home page listing all product features, with each one clearly active or inactive based on whether I'm logged in and how it's configured
**So that** I can discover and enter the features available to me without hitting dead taps or a page that doesn't match the design

**Source:** `RC-1` — *Web app - Home page* (original build: banner, feature grid split into free vs. login-required features, per-feature first-use tip, per-feature first-use intro popup, phone/tablet support) and `RC-106` — *Web App - Fix Home page issue* (child of Epic `RC-101`: feature visibility must follow the Admin feature-config page, RepairCheck-logo click must redirect Home, plus a defect comment — Ann, 2026-07-09 — where a guest-accessible feature ["login required" unchecked in Admin] was a dead tap instead of working per Figma).

> **RC-106 extends/supersedes RC-1's static feature lists.** RC-1 hardcodes which features are free (`Clever tanken`, `Parkplatz Suche`) vs. login-required (`Unfallhilfe`, `Werkstatt Finden`, `Leasing Rückläufe`, `Unfall Rechtsberatung`, `KFZ Aufbereiter`, `Experte für Fahrzeugdiagnose`, `Ein Auto Mieten`). RC-106 says this must instead follow the **Admin feature-config page** (`/admin/features`) per feature. AC/BR below treat the Admin config as the source of truth (BR-HOME-01) and RC-1's lists as the baseline values at authoring time (BR-HOME-02), consistent with how the `expert` and `lawyer` features' own stakeholder overrides were handled.

> **Grounded against `01_SRS/homepage/Screenshot 2026-08-06 at 09.36.25.png`.** This is a partial/cropped screenshot showing only the "LOGGED IN" flow — a Splash screen and a Home screen (banner text, "Book an appointment" / "Create a damage report" actions, a quick-menu icon grid, bottom nav). It is cut off before a second section (visible heading fragment "FIRST REGISTRATIO…"), and no guest-view or inactive-tile state is visible. RC-1's own Figma links (mobile + web) were not fetched — Figma access is out of scope for this skill unless a screenshots folder is passed, and none exists for `homepage` beyond this one file. Treat all exact visual/layout details as **unconfirmed** beyond what's stated in the ticket text.

## Confirmed Decisions (resolved 2026-08-06 — all prior open questions answered)

| #  | Item                                                       | Decision                                                                                                                                                                    |
| -- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1  | Tap behaviour on an inactive/login-required tile           | Navigates the guest to the **Login page** (not a dead tap, not an in-page prompt). Updated AC-HOME-09.                                                                     |
| 2  | "Floating based on the device" exact breakpoints/mechanics | Out of scope for detailed verification — stakeholder confirmed not a priority. AC-HOME-13 downgraded to ⚪ Low; only general responsive behaviour (already covered by AC-HOME-12) needs testing. |
| 3  | Tip/intro-popup "seen" persistence scope                   | Stored via a **browser cookie** — per browser/device, not per user account. Clearing cookies or switching browser/device resets the "seen" state. Updated BR-HOME-04.       |
| 4  | Tip vs. intro popup relationship                           | Feature-specific: a feature's tip/intro only activates once that feature itself is turned **on** (Admin-enabled) — independent per feature, not an all-or-nothing global mechanic. Updated BR-HOME-04. |
| 5  | Mobile vs. web visual design                                | Confirmed the same — no separate mobile/web breakdown needed.                                                                                                               |
| 6  | Other `RC-4` children covering the Home page               | Confirmed none — feature scope stays at `RC-1` + `RC-106`.                                                                                                                  |
| 7  | Admin feature-config schema                                 | Confirmed: simple `enabled` + `loginRequired` boolean pair per feature — no role/market variants. Updated BR-HOME-01.                                                       |
| 8  | Nature of the RC-106 "click doesn't show anything" defect  | Confirmed a **silent no-op** — the tap produces literally no reaction (no blank screen, no JS error). This is exactly what AC-HOME-03 regresses against. Updated AC-HOME-03. |
