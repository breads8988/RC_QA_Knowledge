## User Story

**As a** Repair Check web-app user who needs vehicle diagnosis
**I want** to browse nearby diagnostic experts/workshops and either request a callback appointment or schedule a video call with a specific expert
**So that** I can get expert help arranged without leaving the app

**Source:** `RC-112` — *Web App - Fix Find an Expert page* (child of Epic `RC-101` Web App): UI alignment to Figma + the appointment/video-call icons opening a scheduling link, plus its clarifying/defect comments (Ann — empty expert list 2026-07-08; option-chooser popup not showing 2026-07-13; rating filter showing nothing 2026-07-18; passed staging 2026-07-24).

> **Superseding stakeholder decision (confirmed 2026-07-05, prior session).** RC-112's description states that both the "Get Appointment" and "Schedule a call" icons open the single shared Calendly link `https://calendly.com/alextyl/jaekelgmbh`. This is **superseded**: the two icons are **separate flows** — "Make an appointment" submits an in-app **callback request**; "Schedule a video call" opens a **per-expert** Calendly page in a new tab. AC below follow the decision, not the literal ticket text (see BR-ECA-01/02).

> **Grounded against `01_SRS/expert/Screenshot 2026-08-06 at 09.23.55.png`** (the only image in that folder — no separate `figma` subfolder was passed or exists for this feature). It shows two flows: **"Make an appointment"** (expert list → tap an expert → option-chooser popup with two icons → appointment confirmation prompt "Do you want *Name* to call you back and arrange an appointment?" → "Send Request") and **"Schedule a video call"** (expert list → tap an expert → option-chooser popup → a Calendly-style page branded to that workshop, e.g. "Riparo Workshops," with Select-a-Day → Select-a-Time → Enter Details → "Schedule Event"). No other UI state (error, empty list, rating filter control, loading) is visible in this screenshot — flagged in Open Questions.

> **Scope boundary:** this feature stays **separate** from `lawyer` (`RC-116`) by stakeholder decision, even though both share the list + rating-filter + Calendly pattern. Do not merge or cross-reference their AC.

## Confirmed Decisions (resolved 2026-08-06 — all 10 prior open questions answered)

| #  | Item                                | Decision                                                                                                                                                                 |
| -- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1  | Location-permission-denied fallback    | **Mandatory** — denying location permission shows a warning and the expert list is not displayed. Added AC-ECA-12, updated BR-ECA-03.                                    |
| 2  | Rating filter semantics                | Confirmed **same as `lawyer`**: minimum-rating filter, ≥ N★. Added BR-ECA-05.                                                                                              |
| 3  | Rating scale                           | Filter UI offers whole stars; displayed/aggregate rating may be decimal (e.g. "3.4"), floored to its whole-star bucket for filter matching (3.4 → matches 3★, not 4★). Added BR-ECA-06. |
| 4  | Option-chooser gating                  | Confirmed **always both icons** on every expert selection — no conditional gating. Updated AC-ECA-08.                                                                     |
| 5  | Callback-request persistence           | Only a **"Thank you" confirmation popup** is shown — no separate trackable "Requested" status afterward. Updated AC-ECA-03.                                               |
| 6  | Calendly duration / timezone           | Not a priority — no need to verify call duration or timezone handling.                                                                                                    |
| 7  | Empty-state and error-state copy       | Not a priority — exact copy doesn't need confirmation; existing assumption (an explicit state exists) is sufficient for AC-ECA-09/10/11.                                  |
| 8  | Permissions                            | Access **depends on the Admin feature-config** — same `enabled` + `loginRequired` mechanism as the Home page. Added BR-ECA-07.                                            |
| 9  | Eligible-expert radius                 | **No radius restriction** — default view shows every available expert regardless of distance. Added BR-ECA-04.                                                           |
| 10 | Backend scope                          | Keep **separate** — API tickets' AC are not merged into this feature spec.                                                                                                |
