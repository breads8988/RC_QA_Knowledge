# Acceptance Criteria — Lawyer (`LAW`)

## User Story

**As a** Repair Check web-app user who has had an accident
**I want** to browse a list of lawyers reached from "Unfall Rechtsberatung", narrow it by rating, and book an appointment with one
**So that** I can find and engage suitable legal representation for my accident claim without leaving the app

**Source:** `RC-116` — *Web App – Fix Lawyer page* (child of Epic `RC-101` Web App), plus its clarifying comments (rating-filter semantics — Dai Luong 2026-07-09; sort order — Ann 2026-07-14; iPad display defect — PM-AiVan 2026-07-08).

> **Not grounded against Figma.** The screenshot folder `01_Features/lawyer/wa_lawyer/screens` is **empty**, so no UI states were available. Every element named below ("Unfall Rechtsberatung", "Terminierungsoptionen", "Termin vereinbaren", rating filter) comes from the ticket text only. **Confirmed 2026-08-06:** a lawyer entry displays whatever data fields the design shows — photo, firm name, specialisation, location, distance, contact, and review count all confirmed as part of the entry; exact visual layout still pending a real Figma/screenshot. The filter control type remains **unconfirmed**; empty/error-state copy is confirmed as **not a priority** (no specific requirement — see Confirmed Decisions).

> **Scope boundary:** this feature stays **separate** from `expert_call_appointment` (`RC-112`) by stakeholder decision, even though both share the list + rating-filter + Calendly pattern. Do not merge or cross-reference their AC.

| BR-LAW-01  | The rating filter is a **minimum-rating** filter: selecting N★ returns every lawyer whose rating is **≥ N** (filter 2★ → lawyers rated 2★, 3★ and 4★ are all returned). It is **not** an exact-match filter. | [RC-116](https://motionscloud.atlassian.net/browse/RC-116) | Dev clarification (Dai Luong, 2026-07-09) resolving the defect PM-AiVan reported on 2026-07-08. **Confirmed by stakeholder 2026-08-06** ("2★ → shows result ≥2★"). | 🔴 Critical | `TC-LAW-005` | Draft  |
| BR-LAW-02  | The default order of the lawyer list is **rating descending** — the highest-rated lawyer is always at the top, both unfiltered and within a filtered result. Lawyers with no rating yet are **not excluded** from the default (unfiltered) list; they appear alongside rated lawyers, following the same descending-rating rule (assumed to sort last, since they have no rating value — exact position not explicitly confirmed). No secondary sort key (name, distance, review count) is required to break ties between equally-rated lawyers — any consistent order is acceptable. | [RC-116](https://motionscloud.atlassian.net/browse/RC-116) | Stakeholder request (Ann, 2026-07-14: "highest rate should on top"). Unrated-lawyer inclusion and tie-break confirmed by stakeholder 2026-08-06 ("default hiện tất cả, có rule giảm dần" — by default show all, ordered descending; "không, hiện sao cũng được" — no, any order is acceptable).                                   | 🟠 High     | `TC-LAW-003`, `TC-LAW-004`, `TC-LAW-005` | Draft  |

## Confirmed Decisions (resolved 2026-08-06 — all 14 prior open questions answered)
