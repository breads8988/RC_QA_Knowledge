# Acceptance Criteria — Before Rental (`BRE`)

## User Story

**As a** driver about to rent one of my registered vehicles
**I want** to select the rental vehicle, document its existing damage per zone with guided photos, mark the damaged parts with an AI-estimated repair cost, and then submit and schedule the rental period
**So that** the vehicle's pre-rental condition is captured with enough evidence to protect me from being charged for damage that already existed, and I'm reminded to repeat the process when the rental ends

> **Grounded against `01_Features/rental/wa_before_rental/screens/*.png`** (3 Figma exports covering the full 14-screen flow) and the RC-127 description. Screens are low-resolution thumbnails — exact copy/spacing is unconfirmed beyond what the ticket text states; only structure and states visible in both are used below.

## Open questions / ambiguities

1. **Ad placement (Screens 2/3, 10).** The ticket shows a "Bottom Banner Ad" and a "Large ad banner space" configured in Admin, but `wp_advertisement`'s `AC-WPAD-06` currently lists exactly 8 Target Pages for Banner-type ads, and this flow isn't one of them. Needs confirmation: will Target Pages be extended to cover this flow's screens, or does Screen 10 reuse the existing Damage-page "Advertisement" schedule type (`AC-WPAD-02`) instead of the newer Banner type?
2. **"Screen 12" is missing** from the ticket — it jumps from Screen 11 (AI Estimated Repair Cost) straight to Screen 13 (Submission Success). Unclear if a screen was dropped from the spec or the numbering simply skips 12; flagging so nothing is silently missed.
3. **AI Processing → AI Estimated Repair Cost transition (AC-BRE-27)** is inferred purely from the screens being numbered 10 then 11 — the ticket never states the trigger (auto on completion vs. a tap). Needs confirmation.
4. **No rental vehicles registered.** The ticket doesn't describe an empty state for the Select Car screen when the user has zero Rental-flagged vehicles — not covered above to avoid inventing UI. Needs a defined empty state.
5. **Date validation on the submission success screen (Screen 13).** The ticket doesn't state whether Rental start date / Rental end date are mandatory before "Add event to my calendar" is enabled, nor whether the end date must be after the start date. Not asserted above to avoid inventing a rule.
6. **A Figma frame in the supplied screenshots is named "Capture 360…"** even though its visible content matches the AI Processing screen already described in the ticket (Screen 10). No separate 360°-capture step is mentioned anywhere in the ticket text, so nothing was added for it — flagging in case a screen/requirement was left out of the ticket description.

- **`e_vehicle` backlinks** (`registration`, `my_vehicle`) — read both. `BR-REG-11` (Owner/Rental ownership field) is the mechanism this feature's vehicle filter depends on; `BR-MV-01` / `AC-MV-11` (4-vehicle cap) is the same limit this feature's Register Vehicle button is subject to. No conflicts — this feature consumes both rules rather than redefining them (`BR-BRE-01`, `BR-BRE-02`).

If/when a `wp_` rental-report feature is created, revisit for a matching admin view (the pattern `wp_accident_report` follows for `AA`/`MA`).
- **`accident` domain (`AA`)** — read `wa_accident_assistant_ac.md` in full. The zone-capture diagram, guided camera, thumbnail/delete pattern, and Vehicle Part Details editor are structurally identical to `AA`'s Step 2 and Step 4, and the ticket explicitly ties this UI to "report damage" four times — captured as `BR-BRE-04` / `BR-BRE-05` rather than re-describing `AA`'s own rules. No contradiction with `AA`'s existing `BR-AA-05` (required/optional checklist items) or `BR-AA-06` (multi-select damage types) — `BRE` reuses the multi-select pattern (`BR-BRE-03`) and doesn't reuse the required/optional checklist since this ticket describes no such checklist for `BRE`.
- **`homepage` (`HOME`)** — "Ein Auto Mieten" is already one of `BR-HOME-02`'s baseline login-required tiles, gated by `BR-HOME-01` (Admin feature-config visibility). No new entry-point work implied; confirmed via your answer that the flow starts the same way (Home page → tap "Ein Auto Mieten").
- **`wp_advertisement` (`WPAD`)** — read for the ad-banner screens. Gap found and left unresolved: see Open Question 1 above; not silently assumed either way.
- **Metadata drift**: none found while checking the above — `MV`, `REG`, `AA`, `HOME`, `WPAD` hubs all have populated `entity` links and existing `ac:` files.
